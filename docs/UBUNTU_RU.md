# Установка, запуск и публикация в Ubuntu

Этот документ описывает полный сценарий работы с **CryptoHunter Neural Scalper 0.1.1** в Ubuntu: от распаковки архива до запуска, проверки RTX/CUDA, резервного копирования и публикации private-репозитория на GitHub.

> Версия 0.1.1 работает только в исследовательском и paper-режиме. Кода отправки реальных ордеров нет.

## 1. Самый простой путь

Рекомендуется использовать архив `.tar.gz`, потому что он сохраняет Linux-права выполнения файлов.

1. Распакуйте архив в постоянную папку. Например:

   ```text
   /home/<пользователь>/Applications/CryptoHunter-Neural-Scalper
   ```

2. Откройте терминал в папке проекта.
3. Выполните:

   ```bash
   chmod +x INSTALL_UBUNTU.sh
   ./INSTALL_UBUNTU.sh
   ```

4. После установки откройте меню приложений Ubuntu и запустите:

   ```text
   CryptoHunter Neural Scalper
   ```

5. В браузере откройте страницу **«Главная»** и нажмите **«Запустить демо»**.

Установщик не добавляет программу в системные каталоги и не изменяет исходный код. Всё пользовательское окружение остаётся в папке проекта и в стандартных пользовательских каталогах `~/.local/bin` и `~/.local/share/applications`.

## 2. Что делает `INSTALL_UBUNTU.sh`

Сценарий выполняет следующие действия:

```text
проверка Linux
→ установка curl, сертификатов, Git и xdg-компонентов через apt
→ установка uv из официального установщика Astral
→ установка управляемого Python 3.12 в профиль пользователя
→ создание локальной папки .venv
→ установка requirements.txt
→ создание команд запуска, остановки и публикации в ~/.local/bin
→ создание ярлыков меню приложений
→ попытка создать доверенные ярлыки на рабочем столе
```

Для системных пакетов Ubuntu может запросить пароль `sudo`. Пароль не сохраняется программой и обрабатывается самой операционной системой.

`uv` используется для того, чтобы не зависеть от версии системного Python. Это особенно полезно, если в новой версии Ubuntu системный Python новее, чем поддерживают отдельные ML-библиотеки.

## 3. Где располагать проект

Хорошие варианты:

```text
~/Applications/CryptoHunter-Neural-Scalper
~/Projects/CryptoHunter-Neural-Scalper
~/РабочийСтол/CryptoHunter-Neural-Scalper
```

Нежелательно:

- запускать программу прямо из окна архиватора;
- располагать проект в `/usr`, `/opt` или `/root` без необходимости;
- хранить проект на разделе только для чтения;
- перемещать папку после создания ярлыков;
- запускать программу от `root`.

Папка должна позволять создавать `.venv` и изменять `var/`.

## 4. Запуск

### Через меню Ubuntu

После `INSTALL_UBUNTU.sh` найдите в меню:

```text
CryptoHunter Neural Scalper
```

Откроется терминал сервера, затем браузер с адресом:

```text
http://127.0.0.1:8094/
```

Терминал лучше не закрывать во время работы. В нём видны критические сообщения запуска.

### Из терминала

```bash
cd ~/Applications/CryptoHunter-Neural-Scalper
./start.sh
```

То же самое через явно названный файл:

```bash
./START_UBUNTU.sh
```

### Другой порт

```bash
NEUROSCALPER_PORT=8194 ./start.sh
```

### Другой локальный адрес

По умолчанию сервер слушает только `127.0.0.1`. Это безопасный локальный режим.

Не задавайте `NEUROSCALPER_HOST=0.0.0.0`, пока не добавлены аутентификация, TLS и сетевые ограничения. В версии 0.1.1 HTTP API не рассчитан на открытый интернет.

## 5. Что происходит при первом запуске

`start.sh`:

1. ищет готовое `.venv`;
2. проверяет версию Python;
3. при наличии `uv` создаёт окружение на Python 3.12;
4. рассчитывает SHA-256 для `requirements.txt` и `pyproject.toml`;
5. устанавливает зависимости только при изменении этого SHA-256;
6. создаёт рабочие каталоги `var/`;
7. запускает `neuroscalper.launcher`;
8. ждёт health-check;
9. открывает браузер.

Если старое `.venv` использует неподдерживаемый Python, оно не удаляется. Сценарий переименует его в папку вида:

```text
.venv.unsupported.20260802-153000
```

После успешного запуска такую резервную папку можно удалить вручную.

## 6. Остановка

### Обычная остановка

В терминале сервера нажмите:

```text
Ctrl+C
```

### Отдельный сценарий

```bash
./STOP.sh
```

`STOP_UBUNTU.sh` сохранён как технический совместимый файл; обычному пользователю достаточно `STOP.sh`.

Сценарий:

- читает `var/data/server.pid`;
- проверяет, что PID существует;
- проверяет командную строку процесса;
- не завершает чужой процесс при устаревшем PID;
- сначала отправляет `SIGTERM`;
- использует `SIGKILL` только если штатная остановка не сработала.

Также в меню приложений создаётся ярлык:

```text
CryptoHunter Neural Scalper — Остановить
```

## 7. Если Ubuntu открывает `.sh` как текст

Вариант через терминал:

```bash
chmod +x INSTALL_UBUNTU.sh start.sh START_UBUNTU.sh STOP.sh STOP_UBUNTU.sh
./INSTALL_UBUNTU.sh
```

В файловом менеджере Nautilus:

1. щёлкните файл правой кнопкой;
2. откройте **«Свойства»**;
3. включите разрешение выполнять файл как программу;
4. снова откройте файл и выберите запуск.

Для ярлыка `.desktop` Ubuntu иногда показывает пункт **«Разрешить запуск»**. Это штатная защита рабочего стола.

## 8. Проверка RTX 3090 и CUDA

После установки выполните:

```bash
./CHECK_GPU.sh
```

Сценарий показывает:

- модель NVIDIA GPU;
- версию драйвера;
- объём видеопамяти;
- версию Python;
- версию PyTorch;
- наличие CUDA в PyTorch;
- имя устройства, выбранного для обучения.

Хороший результат для RTX 3090 выглядит по смыслу так:

```text
CUDA доступна: True
Устройство: NVIDIA GeForce RTX 3090
Видеопамять: около 24 ГБ
```

Если `nvidia-smi` работает, но PyTorch сообщает `CUDA доступна: False`, вероятна CPU-сборка PyTorch либо несовместимость драйвера и установленного wheel. Сам интерфейс и paper-функции продолжат работать на CPU.

В настройках программы параметр `model.use_gpu` должен быть включён, чтобы обучение выбрало CUDA. Если CUDA недоступна, код автоматически использует CPU.

## 9. Тестирование

```bash
./RUN_TESTS.sh
```

Сценарий подготовит окружение, установит `requirements-dev.txt` и запустит pytest.

Ручной вариант:

```bash
./start.sh --prepare-only
export PYTHONPATH="$PWD/src"
.venv/bin/python -m pytest -q
.venv/bin/python -m compileall -q src tests integration
node --check src/neuroscalper/web/static/app.js
```

`node --check` выполняется только при установленном Node.js; для обычной работы программы Node.js не требуется.

## 10. Публикация на GitHub

Запустите:

```bash
./PUBLISH_TO_GITHUB.sh
```

Сценарий автоматически:

1. проверит Git;
2. при необходимости установит GitHub CLI из официального APT-репозитория GitHub;
3. откроет браузерную авторизацию `gh auth login --web`;
4. определит имя вошедшего пользователя;
5. создаст локальный Git-репозиторий, если его ещё нет;
6. создаст коммит;
7. создаст private-репозиторий `CryptoHunter-Neural-Scalper`;
8. отправит ветку `main`;
9. создаст и отправит тег по `VERSION.txt`;
10. откроет страницу репозитория.

По умолчанию репозиторий закрытый. Для публичного репозитория:

```bash
GITHUB_VISIBILITY=public ./PUBLISH_TO_GITHUB.sh
```

Другое имя:

```bash
GITHUB_REPO=NeuralScalper ./PUBLISH_TO_GITHUB.sh
```

Явный владелец или организация:

```bash
GITHUB_OWNER=masei17021987-afk ./PUBLISH_TO_GITHUB.sh
```

Сценарий не использует `--force`. Если на удалённом сервере существует несовместимая история, push остановится вместо перезаписи данных.

## 11. Обновление программы

Перед обновлением:

```bash
./STOP.sh
cp -a var "var-backup-$(date +%Y%m%d-%H%M%S)"
```

После обновления файлов:

```bash
./start.sh
```

`start.sh` сам увидит изменение зависимостей по SHA-256 и обновит окружение.

Полное пересоздание окружения:

```bash
./STOP.sh
mv .venv ".venv-backup-$(date +%Y%m%d-%H%M%S)"
./start.sh
```

Папку `var/` при этом не удаляйте.

## 12. Резервное копирование

Остановите программу и скопируйте `var/`:

```bash
./STOP.sh
tar -czf "cryptohunter-var-$(date +%Y%m%d-%H%M%S).tar.gz" var
```

Наиболее важные данные:

```text
var/data/records/             записанный стакан
var/data/config.json          настройки
var/data/paper_state.json     paper-состояние
var/data/neuroscalper.db      журнал
var/models/                   checkpoint-файлы
var/reports/                  отчёты бэктеста
```

## 13. Удаление ярлыков

```bash
./UNINSTALL_UBUNTU_SHORTCUTS.sh
```

Команда удаляет только пользовательские ярлыки и wrapper-команды. Исходный проект, `.venv`, модели и данные остаются на месте.

Полное удаление выполняется вручную после резервного копирования `var/`:

```bash
./STOP.sh
rm -rf ~/Applications/CryptoHunter-Neural-Scalper
```

Перед `rm -rf` обязательно проверьте путь.

## 14. Типовые ошибки

### `Permission denied`

```bash
chmod +x *.sh scripts/*.sh
```

### `sudo: command not found`

Система не является обычной Ubuntu либо используется минимальный контейнер. Установите системные пакеты от имени администратора или используйте уже доступные `curl`, `git` и `uv`.

### `Port 8094 is already in use`

```bash
./STOP.sh
ss -ltnp | grep 8094
```

Либо запустите другой порт:

```bash
NEUROSCALPER_PORT=8194 ./start.sh
```

### Браузер не открылся

Откройте вручную:

```text
http://127.0.0.1:8094/
```

Проверьте health endpoint:

```bash
curl http://127.0.0.1:8094/health
```

### `uv: command not found` после установки

```bash
export PATH="$HOME/.local/bin:$PATH"
./INSTALL_UBUNTU.sh
```

Либо откройте новый терминал.

### Не создаётся `.venv`

Не запускайте проект на разделе только для чтения. Проверьте:

```bash
pwd
ls -ld .
touch .write-test && rm .write-test
```

### Нет данных Binance

Проверьте интернет, системное время и журнал программы. Демо-режим должен работать даже без Binance.

## 15. Работа на сервере без графического интерфейса

```bash
cd /path/to/CryptoHunter-Neural-Scalper
NEUROSCALPER_HOST=127.0.0.1 ./start.sh
```

Для доступа с другого компьютера безопаснее использовать SSH-туннель:

```bash
ssh -L 8094:127.0.0.1:8094 user@server
```

После этого откройте на локальном компьютере:

```text
http://127.0.0.1:8094/
```

Не открывайте порт 8094 напрямую в интернет.
