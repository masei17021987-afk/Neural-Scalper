# Полное руководство пользователя

## 1. Назначение программы

CryptoHunter Neural Scalper — это локальная лаборатория для проверки гипотез скальпинга по стакану. Она объединяет четыре рабочих контура:

1. **рынок** — получает или генерирует события;
2. **анализ** — строит признаки и прогноз;
3. **контроль** — проверяет расходы, качество данных и риск;
4. **исполнение** — моделирует виртуальную заявку и позицию.

Программа не является обещанием доходности и не должна оцениваться только по красивому сигналу на экране.

## 2. Верхняя панель

В верхней части отображаются:

- текущий раздел;
- краткое описание страницы;
- состояние соединения;
- режим работы;
- элементы управления текущим процессом.

Если соединение потеряно, не ориентируйтесь на старое направление сигнала. Проверяйте возраст данных и журнал.

## 3. Главная страница

### Запуск

Кнопка запуска демо создаёт локальный синтетический поток. Кнопка публичного рынка подключает Binance.

При переключении источника предыдущий runtime сначала останавливается, затем создаётся новый. Это защищает от двух параллельных потоков одного символа.

### Цена и капитал

График объединяет:

- цену рынка;
- equity виртуального счёта.

Equity включает плавающий PnL открытой позиции. Balance меняется после комиссий и закрытия позиции.

### Решение системы

Карточка показывает:

- направление;
- уверенность;
- ожидаемое движение до расходов;
- ожидаемое преимущество после расходов;
- режим рынка;
- тип заявки;
- причины;
- предупреждения.

Направление `FLAT` означает, что вход не прошёл хотя бы один из порогов решения.

### Стакан

Отображаются 12 ближайших bid и ask уровней. Полоса силы показывает относительный объём уровня в пределах видимой части книги.

Это визуализация L2-стакана, а не точная очередь отдельных заявок.

### Последние сигналы

Таблица показывает, что увидела система и какой статус получила гипотеза:

- `OBSERVED` — наблюдение без направленного входа;
- `REJECTED` — вход запрещён;
- `ORDERED` — создана виртуальная заявка;
- `SKIPPED` — заявка не создана из-за состояния paper-брокера.

## 4. Рынок и данные

### Демо-рынок

Используйте для:

- проверки интерфейса;
- знакомства со статусами;
- unit/smoke сценариев;
- отладки обучения;
- тестирования бэктеста.

Не используйте синтетику для вывода о реальном PnL.

### Публичный Binance Futures

Collector получает:

- diff depth;
- aggregated trades;
- liquidation/force order events.

Затем он загружает REST snapshot и строит непрерывный локальный стакан.

### Состояние потока

Полезные поля:

- `state` — состояние соединения;
- `messages` — число обработанных сообщений;
- `reconnects` — число переподключений;
- `last_message_ms` — локальное время последнего сообщения;
- `error` — последняя ошибка;
- `retry_seconds` — задержка до следующей попытки.

Повторные переподключения могут быть вызваны сетью, блокировкой домена, тайм-аутом или нарушением последовательности стакана.

## 5. Нейросеть

### Состояние

- `BASELINE` — checkpoint отсутствует;
- `READY` — checkpoint загружен;
- устройство `cpu` или `cuda`;
- путь к активному checkpoint;
- metadata обучения.

### Источник обучения

`synthetic` создаёт новый воспроизводимый датасет с seed 42.

`recorded` читает записанные `book_*.jsonl.gz` выбранного символа.

### Количество примеров

Для synthetic поле задаёт желаемый объём генерации. API ограничивает его диапазоном 800–100 000.

Для recorded фактическое количество определяется доступными файлами и валидными снимками; поле не обрезает всю записанную историю в текущей реализации.

### Прогресс

Этапы:

```text
queued
→ dataset
→ training
→ complete
```

При ошибке состояние меняется на `error`, а текст сохраняется в runtime и журнал запуска.

## 6. Бэктест

### Источник

- synthetic — проверка механики;
- recorded — воспроизведение записанного рынка.

### Количество событий

API допускает 500–2 000 000. Большое значение увеличивает время и потребление ресурсов.

### Показатели

Подробное толкование находится в [BACKTEST_RU.md](BACKTEST_RU.md).

Не сравнивайте два прогона только по net profit. Сначала убедитесь, что количество событий, источник, модель и настройки одинаковы.

## 7. Paper-счёт

### Balance

Закрытая часть капитала с учётом уже списанных комиссий и реализованного PnL.

### Equity

Balance плюс плавающий PnL текущей позиции.

### Peak equity

Максимальный equity, использующийся для high-water drawdown.

### Открытая позиция

Показывает:

- LONG/SHORT;
- количество;
- цену входа;
- текущий PnL;
- стоп;
- take profit;
- trailing anchor;
- время открытия.

### Сброс paper-счёта

Сбрасывает баланс к `initial_balance`, удаляет позицию, ожидающие заявки и внутреннюю историю paper-брокера. Записи SQLite, уже созданные ранее, не удаляются автоматически.

Перед сбросом сохраните `var/data/paper_state.json`, если результат нужен для анализа.

## 8. Настройки

После нажатия **«Сохранить настройки»** значения проходят серверную валидацию и записываются атомарно в `var/data/config.json`.

Изменение символа, глубины стакана или длины последовательности во время работающего потока требует перезапуска источника. Интерфейс получает флаг `restart_required`.

Остальные ограничения риска и исполнения применяются к paper-контуру без сброса счёта.

## 9. Журнал

Журнал объединяет:

- сигналы;
- решения;
- сделки;
- runtime-логи;
- каталог стратегий.

### Как искать проблему

1. найдите время события;
2. посмотрите `action`;
3. прочитайте `reason`;
4. откройте payload;
5. сравните сигнал, риск и состояние рынка;
6. проверьте системный лог в ту же секунду.

Главная ценность журнала — объяснение отказов. Большое число отказов не обязательно является ошибкой: строгий фильтр должен отклонять слабые входы.

## 10. Ежедневный рабочий сценарий

```text
запустить программу
→ проверить health и модель
→ проверить свободное место
→ подключить поток
→ убедиться в CONNECTED
→ проверить data quality
→ наблюдать paper
→ в конце остановить поток
→ сделать резервную копию важных данных
→ проанализировать сделки и отклонения
```

## 11. Перед изменением параметров

Запишите:

- исходные значения;
- цель изменения;
- ожидаемый эффект;
- период данных;
- метрики до изменения.

Изменяйте один логический блок за раз. Одновременное изменение порога модели, комиссий, стопа и размера позиции делает результат неинтерпретируемым.

## 12. Что программа делает автоматически

- нормализует веса модели и правил;
- ограничивает опасные диапазоны;
- сохраняет конфигурацию через временный файл;
- восстанавливает paper-состояние;
- переподключает Binance с backoff;
- останавливает вход при плохом качестве данных;
- переносит лучшую модель в `best_model.pt`;
- сохраняет последний отчёт бэктеста;
- записывает причины отказов.

## 13. Что пользователь обязан контролировать

- свободное место на диске;
- корректность символа;
- качество и длительность данных;
- реальную структуру комиссий аккаунта;
- соответствие моделируемой задержки фактической;
- отсутствие data leakage;
- устойчивость результата на новых периодах;
- резервные копии;
- решение о будущем live-модуле.
