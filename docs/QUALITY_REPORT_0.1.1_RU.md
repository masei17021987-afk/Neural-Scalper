# Отчёт о проверке Ubuntu-сборки 0.1.1

Дата проверки: **2 августа 2026 года**.

## 1. Проверенный объём

Проверялась Ubuntu-ориентированная сборка CryptoHunter Neural Scalper 0.1.1:

- Python-ядро и конфигурация;
- FastAPI HTTP API;
- JavaScript интерфейса;
- Bash-сценарии установки, запуска, остановки, тестов, GPU-проверки и публикации;
- защита GitHub-публикации;
- исключение пользовательских runtime-файлов из Git index;
- локальный запуск сервера с отдельной временной папкой данных;
- создание Git-коммита и тега в локальном испытательном remote.

## 6. HTTP API

Сервер был запущен на отдельном временном порту и с временной переменной:

```bash
NEUROSCALPER_VAR_DIR=<временная папка>
```

Проверены:

```text
GET /health
GET /api/status
```

Подтверждено:

- `/health` вернул `ok: true`;
- версия приложения — `0.1.1`;
- `live_orders_enabled` — `false`;
- при отсутствии checkpoint активен fallback `microstructure_baseline`;
- SQLite и другие рабочие файлы создавались во временной папке;
- сервер слушал только `127.0.0.1`.

## 7. Защитная остановка

`STOP.sh`/`STOP_UBUNTU.sh` проверены в двух сценариях:

1. PID-файл отсутствует — сценарий безопасно сообщает, что программа не запущена.
2. PID принадлежит обычному процессу `sleep` — остановка отказалась завершать чужой процесс и вернула ошибку.

Это подтверждает fail-closed поведение при устаревшем или подменённом PID-файле.

## 8. Симуляция Ubuntu-установки

`INSTALL_UBUNTU.sh` выполнен в изолированной временной папке с тестовыми заменами `uv`, `xdg-user-dir`, `gio` и desktop database.

Проверено:

- создание `.venv`;
- запуск `start.sh --prepare-only`;
- создание wrapper-команд в `~/.local/bin`;
- создание трёх `.desktop` ярлыков;
- права выполнения `755`;
- создание ярлыков на рабочем столе;
- корректная работа, когда путь проекта содержит пробелы.

Фактическая системная установка APT-пакетов и скачивание Python в ходе этой симуляции не выполнялись.

## 9. Предпубликационная защита

Проверены два режима:

```bash
python3 scripts/prepublish_check.py
python3 scripts/prepublish_check.py --staged
```

Проверка выявляет:

- распространённые форматы GitHub/AWS-токенов;
- присвоенные API key/secret;
- приватные ключи;
- `.env` и credential-файлы;
- файлы более 90 МиБ;
- runtime-файлы, если они фактически попали в Git index.

Локальные рабочие данные в `var/` могут существовать, но `.gitignore` и staged-проверка не позволяют добавить их в публикуемый коммит.

## 10. Симуляция публикации на GitHub

Публикационный сценарий был выполнен end-to-end с тестовой командой `gh` и локальным bare Git remote.

Подтверждено:

- инициализация нового Git-репозитория;
- создание ветки `main`;
- создание первого коммита;
- исключение runtime-файлов;
- создание remote;
- push ветки;
- создание и push тега `v0.1.1`;
- отсутствие force push;
- чистое рабочее дерево после публикации.

Фактическое создание репозитория в аккаунте пользователя требует браузерного подтверждения `gh auth login --web` на его компьютере.

## 11. Что не проверялось как успешное

В среде сборки не выполнялись:

- ввод пароля `sudo` пользователя;
- реальная установка пакетов через APT;
- скачивание `uv` и управляемого Python из интернета;
- браузерная авторизация реального GitHub CLI;
- создание реального удалённого репозитория в аккаунте пользователя;
- публичное Binance WebSocket/REST соединение;
- обучение на CUDA/RTX 3090;
- отправка реальных ордеров — соответствующего кода в проекте нет.

Эти ограничения не выдаются за выполненные проверки.

## 12. Итог

Сборка 0.1.1 подготовлена для:

- установки в Ubuntu;
- запуска из меню приложений после однократной настройки;
- демо;
- синтетического обучения;
- событийного бэктеста;
- paper-trading;
- записи публичных рыночных данных;
- безопасной публикации в private GitHub-репозиторий.

Сборка остаётся исследовательской и не является готовой системой торговли реальными средствами.
