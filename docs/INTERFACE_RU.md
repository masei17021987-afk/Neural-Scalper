# Описание интерфейса

## Общие принципы

Интерфейс построен как одностраничное локальное приложение. Все действия выполняются через HTTP API на том же компьютере. Для обычной работы не требуется терминал.

Тёмная тема выбрана для длительного наблюдения. Цвет не является единственным носителем смысла: направление и состояние также подписываются текстом.

## Навигация

Левая панель содержит семь разделов:

```text
Главная
Рынок и данные
Нейросеть
Бэктест
Paper-счёт
Настройки
Журнал
```

Кнопки внутри карточек могут переводить на связанный раздел.

## Главная

### Большая карточка запуска

Назначение — начать демонстрацию без настройки биржевых ключей.

Кнопки:

- **Запустить демо** — старт synthetic runtime;
- **Остановить** — завершить текущий источник;
- переход к публичным данным — открывает страницу рынка.

### KPI-карточки

Обычно отображают:

- цену;
- spread;
- equity;
- PnL;
- режим;
- качество данных;
- состояние модели.

Значение `—` означает отсутствие достаточного количества событий.

### Решение системы

Сигнальная метка:

- LONG;
- SHORT;
- ЖДЁМ/FLAT.

Под ней показываются причины и предупреждения. Причины отвечают на вопрос «почему система склоняется к направлению», предупреждения — «что ослабляет или блокирует вход».

### Стакан

Ask обычно расположен сверху, bid снизу. Mid и spread отображаются рядом. Сила уровня нормализуется по максимальному объёму среди 12 видимых уровней.

## Рынок и данные

### Карточка «Демо-рынок»

Безопасный источник. Не записывается в `records`, потому что synthetic-датасет можно воспроизвести по seed.

### Карточка «Публичный Binance Futures»

Запускает только market-data collector. Отсутствуют поля API key и secret, потому что версия 0.1.1 не использует приватный API.

### Диагностика

Следите за:

- текущим state;
- счётчиком messages;
- reconnects;
- временем последнего события;
- ошибкой;
- data quality score.

## Нейросеть

### Карточка модели

Показывает:

- имя модели или baseline;
- готовность;
- CPU/CUDA;
- путь checkpoint;
- метаданные последнего обучения.

### Форма обучения

Поля:

- источник;
- число synthetic-примеров;
- кнопка запуска.

Пока задача выполняется, повторный запуск блокируется на сервере.

### Объяснение контура

Схема показывает, что нейросеть — лишь один компонент. Итоговое решение зависит также от правил, режима, расходов и риска.

## Бэктест

### Новый прогон

Выберите источник и число событий. Для первой проверки используйте 6 000 synthetic-событий.

### Кривая капитала

Строится по equity после каждого market snapshot. Для интерфейса точки прореживаются, полный итог находится в JSON-отчёте.

### Карточки метрик

Не все метрики годятся для сравнения между источниками. `sharpe_proxy` и `sortino_proxy` рассчитаны по последовательности событий, а не по стандартизированным дневным доходностям.

## Paper-счёт

### Позиция

Когда позиции нет, показывается пустое состояние. При открытии выводятся направление, вход, количество, текущая цена, стоп, цель и PnL.

### Защитный контур

Статус:

- ACTIVE/норма;
- заблокирован kill switch;
- причина блокировки.

Кнопка снятия блокировки не отменяет необходимость разобраться, почему лимит сработал.

### Закрытые сделки

Таблица показывает итог после обеих комиссий и модельного проскальзывания выхода.

## Настройки

Параметры разделены на блоки:

- рынок;
- порог нейросети;
- исполнение;
- риск;
- стратегии.

Знак `?` содержит короткую подсказку. Полная формула и допустимый диапазон находятся в [CONFIGURATION_REFERENCE_RU.md](CONFIGURATION_REFERENCE_RU.md).

### Переключатели стратегий

Отключение компонента исключает его голос из ensemble. Вес оставшихся компонентов пересчитывается внутри агрегатора.

### Сохранение

После сохранения интерфейс показывает результат. Если требуется перезапуск источника, остановите и снова запустите рынок.

## Журнал

### Сигналы

Хранят направление, уверенность, net edge и полный payload.

### Решения

Хранят действие и причину:

- ORDERED;
- REJECTED;
- CLOSED.

### Логи

Показывают последние сообщения memory handler. Полный файл находится в `var/logs/neuroscalper.log`.

## Модальные подтверждения

Опасные действия требуют подтверждения:

- сброс paper-счёта;
- снятие kill switch;
- другие необратимые операции интерфейса.

## Обновление данных

Статус опрашивается периодически. История запрашивается реже, чтобы не создавать лишнюю нагрузку на SQLite и браузер.

## Доступность и масштабирование

Интерфейс рассчитан на настольный браузер. При уменьшении окна карточки перестраиваются, но наиболее информативен экран шириной около 1280–1920 пикселей.

## Что делать, если цифры не обновляются

1. проверьте состояние источника;
2. нажмите обновление журнала;
3. откройте `/health`;
4. посмотрите `last_error` в `/api/status`;
5. проверьте окно сервера;
6. остановите и заново запустите источник;
7. не сбрасывайте данные до чтения логов.
