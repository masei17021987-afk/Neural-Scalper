# Полный справочник настроек

## 1. Где хранятся настройки

Рабочая конфигурация находится в:

```text
var/data/config.json
```

Изменения через интерфейс проходят валидацию и сохраняются. Не редактируйте файл во время работы процесса: последнее сохранение программы может перезаписать ручную правку.

## 2. Общие правила

- неизвестные поля при загрузке игнорируются;
- символ переводится в верхний регистр и очищается от неалфавитно-цифровых знаков;
- числовые значения ограничиваются безопасными диапазонами;
- веса модели и правил автоматически нормализуются до суммы 1;
- неподдерживаемый execution mode заменяется на `paper`;
- перед крупным изменением сохраните копию папки `var/`.

## 3. Секция `market`

### `exchange`

- Тип: строка.
- По умолчанию: `binance`.
- Реализовано в 0.1.1: публичный Binance USD-M Futures collector и synthetic demo.
- Изменение на другое имя само по себе не добавляет новый коннектор.

### `symbol`

- Тип: строка.
- По умолчанию: `BTCUSDT`.
- Формат: биржевой символ без `/`, например `ETHUSDT`.
- Все буквы автоматически становятся заглавными.
- Одновременно обрабатывается один символ.

### `depth_levels`

- Тип: целое.
- По умолчанию: `20`.
- Допустимо валидатором: `5…100`.
- Влияет на размер локального стакана, признаки глубины, нагрузку CPU/RAM и тензор LOB.
- Изменение требует нового обучения, если меняется форма входа модели.

### `update_ms`

- Тип: целое.
- По умолчанию: `100`.
- Валидатор приводит значения `≤100` к 100 мс, остальные к 250 мс.
- Определяет частоту synthetic demo и выбранный Binance depth stream.

### `record_raw_events`

- Тип: bool.
- По умолчанию: `true`.
- Разрешает запись исходных событий, когда collector передаёт их recorder.
- Увеличивает объём диска.

### `record_features`

- Тип: bool.
- По умолчанию: `true`.
- Записывает рассчитанные feature frame в `features_*.jsonl.gz`.
- Для текущего обучения обязательны прежде всего `book_*.jsonl.gz`; feature-файлы полезны для аудита.

### `stale_after_ms`

- Тип: целое.
- По умолчанию: `1500`.
- Используется монитором качества данных.
- Отдельная жёсткая проверка риска блокирует live-вход при возрасте снимка более 2500 мс.

## 4. Секция `model`

### `architecture`

- По умолчанию: `lob_gru`.
- Информационное имя архитектуры.
- Реальная сеть описана в `models/network.py`.

### `sequence_length`

- По умолчанию: `64`.
- Диапазон: `16…512`.
- Число последовательных состояний LOB на один пример.
- Большее значение даёт больше контекста, но повышает память, время обучения и риск переобучения.
- После изменения нужен новый checkpoint.

### `hidden_size`

- По умолчанию: `96`.
- Диапазон: `32…512`.
- Размер скрытого представления GRU и голов сети.
- Для RTX 3090 разумно начинать с 96–192, но качество проверяется экспериментом.

### `dropout`

- По умолчанию: `0.15`.
- Регуляризация во время обучения.
- Слишком высокое значение ухудшает способность модели запоминать полезные короткие структуры.

### `min_confidence`

- По умолчанию: `0.62`.
- Диапазон: `0.34…0.99`.
- Минимальная уверенность для направленного входа.
- Снижение увеличивает число сделок и обычно повышает долю шума.

### `min_net_edge_bps`

- По умолчанию: `1.2` б.п.
- Диапазон: `0…100`.
- Минимальное ожидаемое преимущество после расходов.
- Нулевое значение не означает бесплатную торговлю: комиссии всё равно учитываются в метках и решении.

### `checkpoint`

- По умолчанию: пустая строка.
- Путь к конкретному `.pt` файлу.
- Если пусто, manager ищет стандартный `var/models/best_model.pt`; при отсутствии используется heuristic baseline.

### `use_gpu`

- По умолчанию: `true`.
- При наличии совместимой CUDA-сборки PyTorch используется GPU.
- При отсутствии CUDA программа должна перейти на CPU.

### `mixed_precision`

- По умолчанию: `true`.
- Предназначено для ускорения GPU-обучения и уменьшения VRAM.
- Фактическая поддержка зависит от trainer и устройства.

### `batch_size`

- По умолчанию: `128`.
- Диапазон: `8…4096`.
- Слишком большой batch может вызвать out-of-memory.
- При нехватке VRAM уменьшайте: 128 → 64 → 32.

### `epochs`

- По умолчанию: `8`.
- Диапазон: `1…200`.
- Число проходов по train-набору.
- Лучший checkpoint выбирается по validation, поэтому увеличение не гарантирует улучшение.

### `learning_rate`

- По умолчанию: `0.0008`.
- Базовая скорость оптимизации.
- При нестабильном loss уменьшайте в 2–4 раза.

## 5. Секция `execution`

### `mode`

- Допустимо: `paper`, `demo`, `testnet`.
- По умолчанию: `paper`.
- В версии 0.1.1 все варианты остаются без реальных ордеров; `testnet` не подключает торговый API автоматически.

### `preferred_order_type`

- По умолчанию: `adaptive`.
- Возможные пользовательские значения: `adaptive`, `market`, `limit`, `post_only`.
- Конкретное преобразование в `OrderType` выполняет decision engine.

### `maker_fee_bps`

- По умолчанию: `2.0`.
- Минимум: `0`.
- Комиссия покоящейся лимитной заявки.
- Указывайте ваш реальный тариф с запасом.

### `taker_fee_bps`

- По умолчанию: `5.0`.
- Минимум: `0`.
- Комиссия market-исполнения и закрытия позиции.

### `assumed_latency_ms`

- По умолчанию: `65`.
- Диапазон: `0…5000`.
- Искусственная задержка до активации заявки.
- Для стресс-теста используйте 100–250 мс и выше.

### `queue_factor`

- По умолчанию: `0.65`.
- Диапазон: `0…1`.
- Доля видимого лучшего уровня, считающаяся находящейся перед вашей лимитной заявкой.

### `cancel_after_ms`

- По умолчанию: `900`.
- Время жизни лимитной заявки после активации.
- Слишком короткое снижает fills; слишком длинное повышает adverse selection.

### `slippage_bps`

- По умолчанию: `0.5`.
- Дополнительное ухудшение market fill после прохода по уровням.
- Для низколиквидных пар значение должно быть выше.

### `max_spread_bps`

- По умолчанию: `4.0`.
- Диапазон: `0.1…100`.
- При превышении риск-менеджер запрещает новый вход.

## 6. Секция `risk`

### `initial_balance`

- По умолчанию: `10000.0`.
- Минимум: `10`.
- Начальный paper-баланс и базовая сумма бэктеста.

### `risk_per_trade_pct`

- По умолчанию: `0.25`.
- Диапазон: `0.01…5.0`.
- Процент equity, который позиционный sizing допускает потерять на расстоянии стопа.

### `max_position_notional_pct`

- По умолчанию: `10.0`.
- Диапазон: `0.1…100`.
- Верхняя доля equity в номинале позиции.

### `max_open_positions`

- По умолчанию: `1`.
- В текущем брокере фактически поддерживается одна позиция.

### `max_daily_loss_pct`

- По умолчанию: `2.0`.
- Диапазон: `0.1…50`.
- Достижение включает kill switch.

### `max_drawdown_pct`

- По умолчанию: `10.0`.
- Диапазон: `0.1…90`.
- Просадка от peak equity, после которой включается kill switch.

### `max_consecutive_losses`

- По умолчанию: `5`.
- Диапазон: `1…100`.
- После достижения включается увеличенная пауза.

### `cooldown_seconds`

- По умолчанию: `20`.
- Диапазон: `0…86400`.
- Пауза после закрытой сделки.

### `stop_loss_bps`

- По умолчанию: `18`.
- Диапазон: `1…5000`.
- 18 б.п. = 0,18% от цены входа.

### `take_profit_bps`

- По умолчанию: `30`.
- Диапазон: `1…10000`.
- 30 б.п. = 0,30%.

### `trailing_activation_bps`

- По умолчанию: `18`.
- Уровень прибыли, после которого активируется trailing.

### `trailing_distance_bps`

- По умолчанию: `10`.
- Расстояние trailing stop от лучшей цены.

### `max_holding_seconds`

- По умолчанию: `180`.
- Диапазон: `1…86400`.
- Максимальная длительность виртуальной позиции.

### `allow_dca`

- По умолчанию: `false`.
- Зарезервировано. DCA в 0.1.1 не реализовано.

## 7. Секция `strategies`

Флаги включают или выключают объяснимые компоненты:

- `pulse_enabled` — импульс;
- `drops_enabled` — резкое падение;
- `pumps_enabled` — резкий рост;
- `liquidations_enabled` — поток ликвидаций;
- `volume_enabled` — аномальный объём/дельта;
- `spread_enabled` — состояние спреда;
- `waves_enabled` — волновая/режимная структура.

### `model_weight`

- По умолчанию: `0.55`.
- Вес прогноза нейросети/baseline.

### `rules_weight`

- По умолчанию: `0.45`.
- Вес объяснимых стратегий.

Сумма автоматически нормализуется. Например, 2 и 1 превратятся примерно в 0,667 и 0,333.

## 8. Общие поля

### `language`

- По умолчанию: `ru`.
- Интерфейс версии 0.1.1 ориентирован на русский язык.

### `theme`

- По умолчанию: `graphite`.
- Тёмная графитовая тема.

### `first_run_complete`

- Служебный флаг прохождения начального сценария.

## 10. Изменения, требующие нового обучения

Обязательно переобучайте и повторно тестируйте после изменения:

- `depth_levels`;
- `sequence_length`;
- набора или порядка признаков;
- архитектуры сети;
- горизонта метки;
- формулы расходов;
- символа, если модель не была обучена как multi-symbol;
- режима нормализации.

## 11. Изменения, требующие нового бэктеста

Практически любое торговое изменение:

- комиссии;
- задержка;
- очередь;
- проскальзывание;
- timeout заявки;
- confidence/edge пороги;
- стоп/тейк/trailing;
- риск и номинал;
- веса стратегии;
- включение/выключение компонентов.
