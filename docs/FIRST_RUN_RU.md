# Первый безопасный запуск

Этот сценарий рассчитан на пользователя, который впервые открыл программу и пока не хочет разбираться во внутреннем коде.

## Этап 1. Запустить интерфейс

1. В Ubuntu откройте **CryptoHunter Neural Scalper** из меню приложений либо выполните `./start.sh`.
2. В Windows запустите `START.bat`.
3. Дождитесь открытия браузера.
4. Убедитесь, что сверху отображается название программы.
4. Проверьте, что нет красного сообщения об ошибке запуска.
5. Не подключайте реальную биржу сразу — сначала используйте демо.

## Этап 2. Запустить демо-рынок

На странице **«Главная»** нажмите **«Запустить демо»**.

Через несколько секунд должны изменяться:

- цена;
- режим рынка;
- спред;
- стакан bid/ask;
- график цены;
- количество событий;
- вероятности SHORT / FLAT / LONG;
- человеческое объяснение решения.

Демо-рынок генерирует тренды, боковики, пробои и высокую волатильность. Он нужен для проверки программы, а не для измерения реальной доходности.

## Этап 3. Понять статусы

### `BASELINE`

Обученная нейросеть ещё не загружена. Используется прозрачный микроструктурный baseline. Это нормальный статус первого запуска.

### `READY`

Checkpoint загружен, и решения формируются с участием нейросети.

### `ЖДЁМ` / `FLAT`

Система не видит достаточного преимущества после расходов. Для скальпера это нормальное и частое состояние.

### `REJECTED`

Направленный сигнал был, но риск-менеджер запретил вход. Причина находится в журнале.

### `ORDERED`

В paper-модели создана виртуальная заявка. Это не реальный ордер на бирже.

## Этап 4. Проверить бэктест

1. Перейдите на страницу **«Бэктест»**.
2. Выберите источник `synthetic`.
3. Оставьте 6 000 событий.
4. Нажмите запуск.
5. Дождитесь статуса завершения.

Проверьте:

- количество сигналов;
- количество заявок;
- fill rate;
- количество сделок;
- net profit;
- max drawdown;
- profit factor;
- причины отклонения сигналов.

Положительный синтетический результат не является основанием для реальной торговли. Главное на этом этапе — отсутствие ошибок и логичная работа счёта.

## Этап 5. Обучить тестовую модель

1. Откройте **«Нейросеть»**.
2. Выберите источник `synthetic`.
3. Оставьте 6 000 примеров.
4. Нажмите **«Обучить»**.
5. Наблюдайте прогресс по эпохам.

После завершения создаются:

```text
var/models/lob_scalper_<timestamp>.pt
var/models/lob_scalper_<timestamp>.json
var/models/best_model.pt
var/models/best_model.json
```

Runtime пытается сразу загрузить `best_model.pt`. Статус модели должен смениться с baseline на готовую модель.

Не оценивайте качество по одной accuracy. Важнее recorded-data backtest после расходов.

## Этап 6. Проверить защитный контур

Перейдите в **«Paper-счёт»** и убедитесь, что видны:

- капитал;
- текущая просадка;
- дневной PnL;
- серия убытков;
- риск на сделку;
- статус kill switch.

Кнопку **«Снять аварийную блокировку»** нажимайте только после понимания причины блокировки.

## Этап 7. Подключить публичный Binance

1. Остановите демо.
2. Откройте **«Рынок и данные»**.
3. Проверьте символ, например `BTCUSDT`.
4. Нажмите **«Публичный Binance Futures»**.
5. Следите за состоянием потока.

API-ключ не требуется. Collector использует только публичные рыночные endpoint.

Ожидаемые состояния:

```text
STARTING
→ CONNECTING
→ CONNECTED
```

При разрыве:

```text
RECONNECTING
→ CONNECTING
→ CONNECTED
```

## Этап 8. Убедиться, что данные записываются

Через несколько минут проверьте папку:

```text
var/data/records/BTCUSDT/
```

Должны появиться файлы:

```text
book_YYYYMMDD_HH.jsonl.gz
features_YYYYMMDD_HH.jsonl.gz
```

Файлы делятся по UTC-часам и дописываются в append-only режиме.

## Этап 9. Обучение на записанном рынке

Минимум для технической проверки — несколько часов. Для выводов об устойчивости нужны значительно более длительные периоды и разные режимы рынка.

1. Остановите поток или оставьте его работающим, если диска достаточно.
2. Откройте **«Нейросеть»**.
3. Выберите `recorded`.
4. Запустите обучение.

Программа использует `book_*.jsonl.gz` для выбранного символа.

Если данных недостаточно, появится понятная ошибка. Не пытайтесь исправить её снижением качества меток — продолжите запись.

## Этап 10. Recorded-data backtest

1. Откройте **«Бэктест»**.
2. Выберите `recorded`.
3. Укажите число событий.
4. Запустите прогон.
5. Сохраните отчёт из `var/reports/latest_backtest.json`.

После каждого изменения параметров сравнивайте не только прибыль, но и:

- количество сделок;
- просадку;
- fill rate;
- долю отклонённых сигналов;
- результат по режимам;
- чувствительность к комиссиям, задержке и проскальзыванию.

## Этап 11. Длительный paper-прогон

Рекомендуемый порядок допуска:

```text
демо
→ синтетический бэктест
→ запись реального рынка
→ обучение recorded
→ recorded backtest
→ стресс-тест расходов
→ несколько недель paper/shadow
→ отдельное проектирование live-модуля
```

## Контрольный список первого дня

- [ ] В Ubuntu `./start.sh` или ярлык отработал без ошибки.
- [ ] Демо обновляет рынок и графики.
- [ ] Бэктест завершается.
- [ ] Тестовая модель обучается и загружается.
- [ ] `./RUN_TESTS.sh` проходит; в Windows используется `RUN_TESTS.bat`.
- [ ] Публичный Binance подключается.
- [ ] В `var/data/records` появляются файлы.
- [ ] В журнале нет постоянных sequence-gap.
- [ ] Реальные ордера показываются как заблокированные.
- [ ] Создана резервная копия папки `var` после первых важных данных.
