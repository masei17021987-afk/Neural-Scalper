# Резервное копирование, перенос и восстановление

## 1. Что нужно сохранять

Весь пользовательский результат находится в папке `var/`:

```text
var/data/config.json              — настройки
var/data/paper_state.json         — виртуальный счёт
var/data/neuroscalper.db          — журнал и сделки
var/data/records/                 — записанный рынок
var/data/router_memory.json       — память роутера
var/models/                       — checkpoint и метаданные
var/reports/                      — отчёты
var/logs/                         — диагностика
```

Исходный код можно восстановить из Git, а `var/` — уникальные данные пользователя.

## 2. Полная резервная копия

1. В Ubuntu остановите программу через `./STOP.sh`; в Windows — через `STOP.bat`.
2. Убедитесь, что окно сервера закрыто.
3. Скопируйте всю папку `var/` на другой диск.
4. Для критических данных создайте архив с датой.
5. Проверьте, что архив открывается и содержит файлы записей.

Пример PowerShell:

```powershell
$stamp = Get-Date -Format "yyyyMMdd_HHmmss"
Compress-Archive -Path ".\var\*" -DestinationPath ".\backup\var_$stamp.zip" -Force
```

Для больших `records/` предпочтительнее robocopy:

```powershell
robocopy .\var E:\CryptoHunterBackup\var /MIR /R:2 /W:2 /FFT /Z
```

Перед `/MIR` убедитесь, что путь назначения правильный: зеркалирование удаляет лишние файлы в целевой папке.

## 3. Минимальная копия

Если места мало:

- обязательно: `config.json`, `paper_state.json`, `neuroscalper.db`, `models/`;
- для переобучения: `records/`;
- для диагностики: `logs/`;
- отчёты можно повторно создать, но лучше сохранить.

## 4. Перенос на другой компьютер

1. Установите Python 3.10–3.12 x64.
2. Скопируйте проект без `.venv`.
3. Скопируйте сохранённую папку `var/`.
4. На Ubuntu выполните `./INSTALL_UBUNTU.sh`, затем `./start.sh`; на Windows запустите `START.bat`.
5. Скрипт создаст новое окружение для нового компьютера.
6. На Ubuntu проверьте CUDA через `./CHECK_GPU.sh`; на Windows — через `CHECK_GPU.bat`.
7. Запустите demo, затем небольшой бэктест.
8. Только после проверки запускайте recorded training.

Не переносите `.venv` между компьютерами или разными версиями Python.

## 5. Восстановление `config.json`

Если файл повреждён:

1. остановите приложение;
2. переименуйте файл в `config.broken.json`;
3. запустите приложение;
4. будет создана конфигурация по умолчанию;
5. перенесите нужные параметры вручную через интерфейс.

Не вставляйте весь повреждённый JSON обратно без проверки.

## 6. Восстановление paper state

Если `paper_state.json` не читается, broker очищает опасное состояние. Для ручного сброса:

```bash
./STOP.sh
mv var/data/paper_state.json var/data/paper_state.json.bak
./start.sh
```

На Windows используйте `STOP.bat` и `START.bat`.

Сохраните повреждённый файл для расследования.

## 7. Восстановление SQLite

Сначала остановите приложение и скопируйте:

```text
neuroscalper.db
neuroscalper.db-wal
neuroscalper.db-shm
```

Проверка:

```bash
sqlite3 var/data/neuroscalper.db "PRAGMA integrity_check;"
```

Ожидаемый результат: `ok`.

Если база повреждена:

```bash
sqlite3 broken.db ".recover" | sqlite3 recovered.db
```

После восстановления сравните количество строк по таблицам и не заменяйте оригинал до проверки.

## 8. Повреждённый JSONL.GZ

Gzip может стать нечитаемым после аварии в момент записи. Поскольку файлы делятся по часам, повреждение обычно локализовано.

Действия:

1. сохраните оригинал;
2. проверьте `gzip -t file.jsonl.gz`;
3. попробуйте распаковать читаемую часть;
4. отбросьте последнюю неполную JSON-строку;
5. запишите восстановленную историю в новый файл;
6. не меняйте исходную контрольную сумму молча.

## 9. Checkpoint не загружается

Причины:

- изменилась архитектура;
- изменился `hidden_size`;
- изменились levels/sequence/features;
- checkpoint повреждён;
- несовместима версия PyTorch;
- файл получен из недоверенного источника.

Восстановление:

1. переименуйте `best_model.pt`;
2. запустите baseline без нейросети;
3. проверьте программу;
4. загрузите совместимый checkpoint либо переобучите.

## 10. Версионирование резервных копий

Рекомендуемый формат:

```text
backup/
├── 2026-08-02_before_training/
├── 2026-08-09_after_1week_recording/
└── 2026-08-15_before_config_change/
```

В каждой папке добавляйте `README.txt`:

```text
Версия программы: 0.1.1
Git commit: <sha>
Символ: BTCUSDT
Период записи: ...
Причина копии: ...
```

## 11. Правило 3-2-1

Для ценных датасетов:

- 3 копии;
- 2 разных типа носителя;
- 1 копия вне основного компьютера.

## 12. Что не следует коммитить в GitHub

- `.venv/`;
- `var/data/records/`;
- SQLite с личной историей;
- API keys;
- `.env`;
- большие checkpoints, если нет Git LFS;
- логи с потенциально чувствительными данными.
